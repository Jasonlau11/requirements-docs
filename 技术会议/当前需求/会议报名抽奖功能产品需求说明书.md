# 会议报名抽奖功能产品需求说明书

## 1. 需求概览

在会议详情页报名区域下方新增抽奖区域（见原型红框位置，位于报名表单/报名按钮之后、广告位之前）。用户通过平台问卷提交报名成功后，立即获得本会议 1 次抽奖机会；抽奖不再绑定签到，已报名用户即可参与。抽奖可以在报名成功后立即进行，也可以稍后再次打开该会议详情页继续。

运营端按会议配置抽奖开关、奖项、奖品类型、奖品数量、是否需要收货信息和抽奖展示形式。参会端支持大转盘、九宫格、刮刮乐、盲盒四种展示形式；每个会议独立选择一种形式。

本期闭环：**运营配置 -> 用户报名成功提示 -> 会议详情页抽奖入口 -> 服务端开奖 -> 结果展示 -> 需要收货信息时填写并确认 -> 运营端导出全部抽奖结果**。

## 2. 业务规则

### 2.1 抽奖资格

1. 平台问卷提交成功并生成报名记录后，用户获得本会议 1 次抽奖资格；外链报名沿用现有口径，平台问卷提交并点击外链即记录报名成功。平台不等待第三方回传。
2. 抽奖开关关闭：会议详情页不展示抽奖区域。
3. 抽奖开关开启时，会议详情页对所有访问者展示抽奖区域和奖项。未报名用户抽奖次数为 `0`，开始按钮置灰不可用，并提示“报名后可获得 1 次抽奖机会”；不创建抽奖记录。
4. 已报名未签到用户：可以抽奖；签到不是抽奖前置条件。
5. 已报名已签到未抽奖用户：在会议详情页展示“立即抽奖”。
6. 已抽奖用户：展示历史结果，不再展示抽奖按钮。
7. 同一用户同一会议最多一次抽奖。重复打开详情页、重复报名、重复点击和跨端访问均不能增加次数。
8. 报名成功后可立即抽奖，也可以在报名成功弹窗中点击“稍后再说”，之后重新打开同一会议详情页继续。

### 2.2 报名成功提示

现有“跳转到新的报名成功页面”改为当前页面弹窗或底部弹层，不离开会议详情页。

推荐内容：

> 报名成功
> 已获得 1 次抽奖机会
> [立即抽奖] [稍后再说]

- 点击“立即抽奖”：关闭报名成功弹窗，回到当前会议详情页的抽奖区域并自动滚动/定位到该区域，随后由用户点击抽奖形式中的开始操作。
- 点击“稍后再说”或关闭弹窗：停留在会议详情页，用户可以继续浏览；之后再次打开本会议详情页时，抽奖区域展示“立即抽奖”。
- 弹窗关闭、页面刷新或离开后，不影响报名记录和抽奖资格。
- 报名提交失败、未生成报名记录或重复提交未产生新报名记录时，不显示“报名成功并获得抽奖机会”；只要本次提交已生成报名记录，即按已报名处理并获得 1 次抽奖资格。

### 2.3 抽奖入口与结果

抽奖区域位于会议详情页报名区域下方。

| 用户状态 | 展示 |
|---|---|
| 未报名 | 展示抽奖区域、完整奖项和 `0` 次抽奖机会；开始按钮禁用，可提供“立即报名”引导。 |
| 已报名未抽奖 | 展示活动标题、奖项展示、`1` 次可用机会和“立即抽奖”。不要求先签到。 |
| 抽奖处理中 | 禁用开始操作，展示处理中。 |
| 已抽奖且中奖 | 展示奖项名称、类型、说明、抽奖时间；若该奖项要求收货信息，展示收货信息填写/待确认状态。 |
| 已抽奖且谢谢参与 | 展示安慰奖名称和说明。 |
| 抽奖关闭 | 不产生新结果；历史结果仍可查看。 |

抽奖资格和结果以服务端为准，前端不能仅依赖本地缓存判断。

## 3. 运营端配置

### 3.1 入口

运营端：**会议管理 > 会议详情 > 抽奖配置**。每个会议独立配置一份抽奖规则。默认开关关闭。

### 3.2 默认配置

首次打开会议的抽奖配置时，自动生成：一等奖、二等奖、三等奖、谢谢参与。默认概率为 0%、0%、0%、100%。运营可开启后直接使用默认配置，也可以先调整再开启。默认配置不代表平台承诺实际奖品。

### 3.3 基础配置

| 字段 | 规则 |
|---|---|
| 开启抽奖 | 开关；关闭时参会端不展示抽奖区域。 |
| 活动标题 | 可选，参会端展示。 |
| 活动说明 | 可选，参会端展示。 |
| 抽奖形式 | 大转盘、九宫格、刮刮乐、盲盒四选一；与奖品类型、数量、收货信息配置相互独立。 |

### 3.4 奖项配置

运营可新增、删除、编辑和排序奖项；奖项保存即生效，删除即停止后续展示和开奖，不单独提供启用/停用状态。

| 字段 | 规则 |
|---|---|
| 奖项名称 | 必填，1 至 20 个字符。 |
| 奖品类型 | 有效奖品、谢谢参与。有效奖品不再区分实物或虚拟。 |
| 概率 | 必填，支持两位小数；配置中全部奖项合计必须精确为 100.00%。 |
| 奖品数量 | 有效奖品必填，为大于等于 0 的整数；谢谢参与不限量。 |
| 需要收货信息 | 独立开关，与奖品类型不绑定；开启后该奖项中奖用户必须填写并确认收货信息。 |
| 展示顺序 | 控制参会端位置，不影响概率。 |

奖项保存即生效，删除奖项即停止其后续展示和开奖；不单独提供奖项启用/停用状态。

配置校验：

- 至少保留 2 个奖项。
- 全部已保存奖项概率不等于 100.00% 时，配置可以继续编辑，但保存开关为开启的操作必须被拒绝，并提示当前合计和差额。
- 概率为 0% 的奖项可以保存和展示，但不会被抽中。
- 运营可以删除默认奖项；删除后不自动补充假奖项。
- 九宫格最多支持 9 个已保存奖项（谢谢参与也计数）。奖项超过 9 个时，运营端不允许选择九宫格，并提示需减少奖项或选择其他形式；大转盘、刮刮乐、盲盒本期不做数量限制。
- 已有历史结果的奖项删除或改名，不得改写历史记录中的奖项快照。

### 3.5 实时预览

- 配置页提供与奖项编辑区并列或相邻的实时预览区域。运营每次切换大转盘、九宫格、刮刮乐、盲盒，或调整奖项名称、类型、顺序后，预览立即同步最终参会端展示效果。
- 预览使用当前未提交的编辑态数据也能刷新，便于运营在保存前确认布局；不展示概率、奖品数量或运营内部字段。
- 预览不调用真实开奖接口、不创建抽奖记录、不扣减奖品数量；其中的转动、刮开或开盒动画仅为演示态。
- 九宫格预览最多展示 9 个奖项；奖项超过 9 个时直接显示超限提示，并同步禁用九宫格选择。

### 3.6 数量与抽奖规则

1. 有效奖品的奖品数量为可发放上限；每次抽中后服务端原子扣减 1，数量不能为负或超发。
2. 开奖前将数量为 0 的有效奖品从**开奖候选集合**移除，但这些奖项仍保留在参会端**展示集合**，不隐藏、不变灰、不改变位置或大小。
3. 剩余候选奖项按运营配置的原始概率重新归一化；谢谢参与不限量，始终参与候选集合。
4. 当所有真实奖品数量都为 0 时，展示集合仍完整保留，候选集合只剩谢谢参与，后续用户仍可抽奖，结果为 100% 谢谢参与。
5. 并发抽奖导致库存扣减失败时，服务端重新读取数量并重新按候选集合开奖；最多重试 3 次，仍失败则返回谢谢参与。
6. 概率只在运营端可见；参会端不展示概率、数量、剩余量或实际归一化后的概率。奖品类型在参会端可按结果需要展示为“有效奖品”或“谢谢参与”，不展示实物/虚拟分类。

## 4. 收货信息

### 4.1 填写规则

仅当抽中奖项的“需要收货信息”开关为开启时，结果页展示收货信息表单。

字段：收货人姓名、收货手机号、省、市、区/县、详细地址。收货手机号默认填入报名手机号，但允许修改。

- 用户必须填写并点击“确认收货信息”后，才算收货信息完成。
- 用户可以先关闭结果弹层或离开页面，中奖结果已经落库；再次打开该会议详情页时继续展示“请完善收货信息”。
- 未确认前不影响用户查看中奖结果，但不得显示为“收货信息已完成”。
- 收货信息一旦确认，不允许用户修改。若填错需联系运营线下处理，本期不提供自助修改。
- 未开启收货信息的奖项或谢谢参与奖项，不展示收货信息表单。

### 4.2 推荐文案

中奖：**恭喜你，获得「{奖项名称}」**

需要收货信息：**请填写收货信息，以便主办方发放奖品。确认后将无法修改。**

提交成功：**收货信息已确认，主办方将按活动安排发放奖品。**

未填写时：**你可以稍后回到本会议详情页补充收货信息。**

不建议平台统一承诺“运营会联系您”，因为不同会议可能采用现场领取、统一寄送或电子发放。发放履约由运营根据活动说明执行。

## 5. 四种抽奖形式

每个会议独立选择一种形式，形式只决定视觉和交互，不改变奖项概率、数量或收货信息规则。四种形式都由服务端先确定结果，前端只负责展示：

| 形式 | 交互要求 |
|---|---|
| 大转盘 | 用户点击开始，动画指向服务端返回的奖项。 |
| 九宫格 | 最多 9 个已保存奖项；不足 9 个时按当前奖项布局展示，不新增隐形奖项。 |
| 刮刮乐 | 用户执行刮开动作后展示服务端结果；刮开区域不影响概率。 |
| 盲盒 | 用户选择/打开盲盒仅为视觉动作，不同盲盒不绑定不同概率，结果由服务端提前确定。 |

统一视觉规则：所有展示奖项使用等大或等权重视觉规格；1% 和 99% 不得通过面积、颜色、字号、位置、动画时长或其他样式体现差异。

## 6. 接口与数据

### 6.1 参会端接口（`csdn_meeting_client`）

| 接口 | 说明 |
|---|---|
| `GET /api/meetings/{meetingId}/checkin-lottery/status` | 查询抽奖开关、展示形式、奖项展示集合、当前用户报名状态、抽奖次数和历史结果。开关开启时，未报名用户也可获取展示所需奖项信息，但返回资格为 `0` 且不可开奖。 |
| `POST /api/meetings/{meetingId}/checkin-lottery/draw` | 请求携带 `clientRequestId`；服务端校验用户已报名（不要求签到），按概率和数量开奖，扣减数量并幂等返回结果。 |
| `PUT /api/meetings/{meetingId}/checkin-lottery/shipping-info` | 为需要收货信息的中奖记录提交一次收货信息；服务端校验本人、奖项要求和未确认状态。 |

抽奖结果接口不得接受客户端提交的用户 ID、奖项 ID、概率、随机数、数量或动画位置作为开奖依据。

### 6.2 运营端接口（`csdn_meeting_operation`）

| 接口 | 说明 |
|---|---|
| `GET /v1/meetings/{meetingId}/checkin-lottery` | 查询当前配置、默认奖项、概率合计、九宫格校验和结果摘要。 |
| `PUT /v1/meetings/{meetingId}/checkin-lottery` | 保存开关、形式、标题、说明和奖项配置；服务端校验字段、数量、九宫格限制和概率合计。 |
| `GET /v1/meetings/{meetingId}/checkin-lottery/records` | 分页查询全部抽奖结果及收货信息完成状态。 |
| `GET /v1/meetings/{meetingId}/checkin-lottery/records/export` | 导出该会议全部抽奖结果。 |

### 6.3 数据模型（逻辑）

| 表/实体 | 核心字段 |
|---|---|
| `t_checkin_lottery_config` | `meeting_id`、`enabled`、`draw_type`、`title`、`description`、`items_json`、审计字段。奖项保存名称、类型（有效奖品/谢谢参与）、概率、数量、是否需要收货信息、展示顺序和稳定 `prizeKey`。 |
| `t_checkin_lottery_record` | `meeting_id`、`user_id`、`registration_id`、`client_request_id`、`prize_key`、奖项快照、`drawn_at`、收货信息快照、`shipping_confirmed_at`。对 `(meeting_id,user_id)` 唯一。 |
| `t_checkin_lottery_inventory` | 奖项当前剩余数量及消耗流水；由参会业务服务原子扣减，避免并发超发。 |

历史记录必须保留中奖时奖项名称、类型、说明、图片、是否需要收货信息和领取信息快照；运营后续修改配置不得改写历史。

### 6.4 导出字段

导出某一场会议的全部抽奖结果，每行一个抽奖用户，包含：

| 列 | 说明 |
|---|---|
| 会议 ID | 当前会议标识。 |
| 会议名称 | 当前会议名称快照或导出时名称。 |
| 用户名 | 运营侧展示的用户本人用户名。 |
| 用户 ID | 用户标识，便于追溯。 |
| 报名手机号 | 报名记录中的手机号。 |
| 抽奖时间 | 服务端开奖时间。 |
| 奖品名称 | 抽奖结果名称，包括谢谢参与。 |
| 奖品类型 | 有效奖品、谢谢参与。 |
| 结果类型 | 真实奖品 / 谢谢参与。 |
| 是否需要收货信息 | 是/否。 |
| 收货信息状态 | 未填写 / 已确认；不需要时为不适用。 |
| 收货人 | 需要且已填写时导出，否则为空。 |
| 收货手机号 | 需要且已填写时导出，否则为空。 |
| 省、市、区/县 | 需要且已填写时导出，否则为空。 |
| 详细地址 | 需要且已填写时导出，否则为空。 |

## 7. 异常、安全与验收

### 7.1 必须满足

- 报名成功弹窗不跳转新页面；关闭后可从会议详情页继续抽奖。
- 报名成功即获得资格，签到不是前置条件。
- 抽奖开关关闭时不展示抽奖区域；开关开启时未报名用户展示完整抽奖区域，但抽奖次数为 `0`、按钮禁用且不能调用成功开奖。
- 抽奖记录由服务端创建，用户身份来自登录态；同一会议同一用户只有一条记录。
- 概率合计不为 100.00% 时不能开启，前后端都校验。
- 数量为 0 的真实奖品不再被抽中，但仍保留在展示集合；只剩谢谢参与时继续抽奖并返回谢谢参与。
- 需要收货信息的中奖用户必须确认后才完成填写；确认后不可修改。
- 导出包含全部抽奖用户，包括谢谢参与；不需要收货信息的奖项行，收货字段为空；需要收货信息的有效奖品按填写情况导出。
- 四种抽奖形式均可按会议单独选择；九宫格超过 9 个已保存奖项时不能选择。
- 小程序、H5、PC 三端使用同一资格、开奖和结果接口；结果展示只在服务端结果返回后进行。

### 7.2 安全与异常

- 网络超时先查询结果，确认未落库后才用原 `clientRequestId` 重试。
- 动画失败不影响已落库结果，刷新后直接展示结果。
- 收货信息接口只能由中奖用户提交一次，运营端只能查看和导出，不能代替用户伪造提交。
- 兑换码、收货信息和手机号遵循现有权限、脱敏、日志和导出安全规范。
