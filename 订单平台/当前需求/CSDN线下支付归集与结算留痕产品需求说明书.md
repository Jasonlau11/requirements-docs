# CSDN 线下支付归集与结算留痕产品需求说明书

## 需求概览

### 核心摘要

本需求对订单平台现有线下支付路径进行最小范围调整。客户不再向接单方账户直接付款，而是统一向 CSDN 指定收款账户线下付款；接单方继续填写自己的结算账户，供 CSDN 在线下完成抽成、会计处理后向其转账。订单平台不参与真实资金执行，不计算佣金、税费或接单方净收入，仅记录账单金额、两类账户、客户付款凭证、运营确认 CSDN 已收款、运营确认 CSDN 已向接单方完成结算等业务结果。

账单状态继续复用现有枚举：客户上传付款凭证后，账单保持待支付并显示“付款凭证待运营核验”；运营根据线下财务反馈确认 CSDN 已收款后，账单进入已支付；运营根据线下财务反馈确认已完成向接单方结算后，账单进入已入账。正常正额账单只有达到已入账，才计入订单已结算判定。

客户开票需求通过账单详情中的“开票咨询”入口承接。平台展示运营配置的企业微信或官方客服二维码及账单信息，客户扫码后在线下提交开票资料，由 CSDN 运营、财务在线下处理。平台不建设开票申请单、抬头管理、发票状态、发票文件或红冲能力。

### 文档定位与适用优先级

本文件为《账单与结算产品需求说明书》的专项补充需求，适用于线下支付归集、CSDN 收款确认、向接单方结算留痕及开票咨询入口。

- 本文件与现有需求中“客户向接单方账户直接付款”“接单方确认客户付款到账”等内容冲突时，以本文件为准。
- 未在本文件中调整的账单生成、阶段结算、金额确认与改价、无尾款、0 元尾款、账单关闭、申诉、退款申请、终止结算和调账规则，继续沿用现有需求。
- 本文件只以 `docs/` 下现有需求文档为业务依据，不以原型实现反推需求逻辑。

# 第1章：概述

## 1.1 背景与问题

现有线下支付流程由接单方填写收款账户，客户直接向接单方付款并上传凭证，接单方确认收款后推进账单状态。该路径使订单平台仅记录双方直付结果，客户款项未经过 CSDN 统一归集，平台无法落实“客户向 CSDN 付款、CSDN 完成抽成后再向接单方结算”的业务要求。

甲方要求线下支付同样先进入 CSDN 指定账户。真实到账核验、平台抽成、会计记账、税务处理及向接单方转账均由甲方财务、会计和运营在线下完成，订单平台只需提供必要账户信息、凭证上传、人工确认和状态留痕，不建设完整财务结算系统。

## 1.2 建设目标

1. 客户可在待支付账单中查看 CSDN 指定收款账户，并向该账户完成线下付款。
2. 接单方可填写并维护自己的结算账户，供 CSDN 在线下向其转账。
3. 运营可根据线下财务反馈确认 CSDN 已收款，并记录操作凭证。
4. 运营可根据线下财务反馈确认 CSDN 已向接单方完成结算，并记录实际结算结果。
5. 正额账单只有完成向接单方结算后才计入订单已结算。
6. 客户可通过账单详情中的二维码联系运营办理开票，不增加平台开票系统。

## 1.3 非目标

本期明确不建设以下能力：

- 自动计算平台佣金、抽成、税费、手续费或接单方净收入；
- 独立支付单、分润单、结算单、钱包、提现和资金流水系统；
- 银行流水自动读取、自动匹配和自动对账；
- 在线支付、支付回调、自动分润、失败重试和部分成功处理；
- 分润回滚、提现追偿、欠款、垫资和自动原路退款；
- 发票抬头管理、税号校验、开票申请单、开票状态、发票下载和红冲；
- 会计科目、税务处理、财务凭证生成和复杂财务权限体系；
- 部分到账、超额到账、重复付款的自动识别与系统化处理；
- 自动 SLA、超时升级、多级催办和财务运营看板。

上述事项由甲方财务、会计、运营等团队在线下处理。订单平台仅记录账户、凭证、操作结果和必要备注。

## 1.4 用户故事

- 作为客户，我希望在账单中查看 CSDN 指定收款账户，以便按平台要求完成线下付款。
- 作为客户，我希望上传付款凭证并查看核验结果，以便知道 CSDN 是否已确认收到款项。
- 作为接单方，我希望填写自己的结算账户，以便 CSDN 在线下向我支付结算款项。
- 作为接单方，我希望客户无法查看我的结算账户，以避免不必要的敏感信息暴露和绕过平台直接交易。
- 作为运营，我希望根据财务反馈确认 CSDN 已收款，以便账单状态与线下资金事实保持一致。
- 作为运营，我希望记录 CSDN 已完成向接单方结算，以便账单和订单能够完成闭环。
- 作为客户，我希望在 CSDN 确认收款后扫码联系运营办理开票，以便完成线下开票流程。

## 1.5 术语表

| 术语 | 描述 |
|---|---|
| CSDN 收款账户 | 客户线下付款使用的 CSDN 指定账户，由运营维护并向客户展示。 |
| 接单方结算账户 | CSDN 在线下向接单方转账使用的账户，由接单方填写，仅接单方和运营可见。 |
| 付款凭证待运营核验 | 客户已上传付款凭证，但运营尚未根据线下财务反馈确认 CSDN 收款；该阶段账单主状态仍为待支付。 |
| CSDN 已收款 | 运营根据线下财务反馈确认 CSDN 已收到客户款项；账单状态为已支付。 |
| 平台已完成结算 | 运营根据线下财务反馈确认 CSDN 已完成抽成、会计处理及向接单方转账；账单状态为已入账。 |
| 实际结算金额 | 运营确认完成结算时记录的、CSDN 实际向接单方支付的金额；仅作留痕，系统不计算、不校验。 |
| 开票咨询 | 客户通过二维码联系 CSDN 运营或客服，在线下提交开票资料并办理开票；不代表平台已受理或承诺开票。 |

# 第2章：功能需求

## 2.1 双账户规则

### 2.1.1 CSDN 收款账户

1. CSDN 收款账户由运营在后台进行简单维护。
2. 最小配置项包括账户名称、开户行、银行账号、展示说明、二维码或附件说明（如有）、启用状态。
3. 本期只要求存在一条当前启用的 CSDN 收款账户，不建设多账户路由、币种、适用范围、版本审批和历史账户管理。
4. 账单进入待支付时，客户侧展示当前启用的 CSDN 收款账户。
5. 账单保存本次付款所使用的 CSDN 收款账户快照，后续后台修改账户不影响历史账单展示。
6. 接单方可查看客户统一向 CSDN 付款的说明，但不得将自己的结算账户提供给客户作为付款账户。

### 2.1.2 接单方结算账户

1. 保留接单方填写收款银行、银行卡号、开户名等能力，字段名称统一调整为“接单方结算账户”。
2. 接单方在账单草稿中填写账单金额、接单方结算账户及必要说明。
3. 客户确认账单时只确认账单金额和业务内容，不查看、不确认、不修改接单方结算账户。
4. 接单方结算账户仅接单方本人和运营可见；列表默认脱敏，详情按权限展示。
5. 接单方可在运营确认 CSDN 已收款前修改结算账户。
6. 运营确认 CSDN 已收款后，接单方结算账户锁定。确需变更时，由接单方联系运营说明情况，运营处理并记录修改原因；本期不新增独立账户变更审批流程。
7. 运营确认完成结算时，保存本次实际使用的接单方结算账户快照；后续账户变化不得影响历史账单。
8. 无尾款不要求填写接单方结算账户。
9. 0 元尾款沿用现有“完整流程留痕”规则，仍填写接单方结算账户，但不发生客户付款及 CSDN 向接单方实际转账。

### 2.1.3 数据项

| 字段 | 必填 | 可见角色 | 说明 |
|---|---:|---|---|
| CSDN 收款账户名称 | 是 | 客户、接单方、运营 | 客户付款使用的账户户名。 |
| CSDN 收款开户行 | 是 | 客户、接单方、运营 | 客户付款使用的开户行。 |
| CSDN 收款银行账号 | 是 | 客户、接单方、运营 | 客户付款使用的银行账号。 |
| CSDN 收款账户快照 | 是 | 客户、接单方、运营 | 账单进入待支付时保存，历史账单不随配置变更。 |
| 接单方结算开户名 | 正额账单是 | 接单方、运营 | CSDN 向接单方转账使用。 |
| 接单方结算开户行 | 正额账单是 | 接单方、运营 | CSDN 向接单方转账使用。 |
| 接单方结算银行账号 | 正额账单是 | 接单方、运营 | CSDN 向接单方转账使用。 |
| 接单方结算账户快照 | 结算确认时是 | 接单方、运营 | 记录运营确认结算时实际使用的账户。 |
| 账户修改原因 | 条件必填 | 接单方、运营 | 锁定后由运营调整账户时记录。 |

## 2.2 账单草稿与客户确认

1. 账单生成触发、阶段账单、整单账单、尾款账单和调账单规则继续沿用现有需求。
2. 正额账单草稿由接单方填写账单金额和接单方结算账户。
3. 客户收到待确认账单后，只核对金额、关联订单、关联里程碑、款项性质和业务说明。
4. 客户不得看到接单方结算账户，避免敏感信息暴露和客户绕过 CSDN 直接付款。
5. 金额改价及双方重新确认规则继续沿用现有需求；接单方结算账户修改不触发客户重新确认。
6. 客户确认金额和业务内容后，账单进入待支付，并关联当前 CSDN 收款账户快照。

## 2.3 客户向 CSDN 线下付款

### 2.3.1 客户操作

1. 账单处于待支付时，客户侧展示 CSDN 收款账户、账单金额、账单编号、订单编号和付款说明。
2. 客户线下付款后点击“我已向 CSDN 完成线下付款”。
3. 客户填写流水号或付款备注，并上传付款凭证；是否强制上传延续现有配置规则。
4. 系统记录客户提交时间、操作者、凭证附件和流水号/备注。
5. 提交后账单主状态仍为待支付，页面显示“付款凭证待运营核验”。
6. 客户在运营完成核验前可补充凭证或说明；是否允许删除已上传附件沿用平台通用附件规则。

### 2.3.2 异常处理

1. 本期不自动识别付款主体、到账金额、部分付款、超额付款、重复付款或错误账户。
2. 运营发现凭证无效、信息不足或财务未查到款项时，执行“驳回补证”并填写原因。
3. 驳回后账单保持待支付，客户可重新提交凭证。
4. 客户对核验结果有异议时，沿用现有申诉与运营人工处理能力。

## 2.4 运营确认 CSDN 已收款

1. 运营在账单管理中查看待支付且已上传付款凭证的账单。
2. 运营根据甲方财务、会计在线下提供的实际到账反馈进行判断，订单平台不连接银行账户、不验证流水真实性。
3. 运营确认前，应能查看账单金额、CSDN 收款账户快照、客户凭证、流水号/备注和关联订单。
4. 运营点击“确认 CSDN 已收款”，可填写核验备注并上传可选附件。
5. 确认后账单从待支付进入已支付，记录确认人和确认时间；接单方结算账户同时锁定。
6. 已支付表示 CSDN 已收到客户款项，不表示接单方已经收到结算款项。
7. 系统通知客户和接单方：CSDN 已确认收款，等待平台线下结算。
8. 接单方不再拥有“确认客户付款到账”或等同操作，也不再适用原有确认收款时限。

## 2.5 运营确认已向接单方完成结算

1. 账单处于已支付时，运营可查看接单方结算账户完整信息，供甲方财务、会计在线下转账。
2. CSDN 在线下完成平台抽成、会计处理及向接单方转账后，运营执行“确认已完成结算”。
3. 确认表单包括：实际结算金额、结算流水号/说明、可选结算凭证、备注。
4. 实际结算金额由运营根据线下结果填写，只作留痕；系统不根据账单金额计算、不校验平台抽成、税费或其他扣减。
5. 运营确认时保存本次实际使用的接单方结算账户快照、操作者和确认时间。
6. 确认后账单从已支付进入已入账。
7. 接单方不需要再次确认到账。如接单方对结算结果有异议，沿用现有申诉入口，由运营人工处理。
8. 未完成线下结算时，账单保持已支付；本期不增加分润中、分润失败、部分成功或自动重试状态。

## 2.6 账单与订单状态协同

### 2.6.1 状态定义

| 账单状态 | 本需求下的业务含义 |
|---|---|
| 草稿 | 接单方待填写金额和接单方结算账户。 |
| 待确认 | 客户待确认金额和业务内容。 |
| 待支付 | 等待客户向 CSDN 付款；客户上传凭证后仍保持该状态，并显示待运营核验。 |
| 已支付 | 运营已确认 CSDN 收到客户款项，尚未确认完成向接单方结算。 |
| 已入账 | 运营已确认 CSDN 完成向接单方结算。 |
| 待退款/退款待客户确认 | 线下退款过程留痕，实际退款由运营协调。 |
| 已冲销/已关闭 | 沿用现有定义。 |

### 2.6.2 订单已结算判定

1. 正常正额账单必须达到已入账，才视为该账单完成结算。
2. 账单仅达到已支付时，订单继续保持待结算。
3. 订单下全部应结账单均达到已入账，或按现有规则合法关闭、冲销、退款结案、无尾款完结后，订单方可进入已结算。
4. 无尾款经现有双方确认流程完结后，继续视为尾款侧已闭环。
5. 0 元尾款不发生实际付款和转账，完成现有账单确认留痕后视为闭环，不要求运营虚构确认收款或结算动作。
6. 已终止订单继续保持已终止，不因历史账单已入账而改为已结算；终止后结算结果按现有规则单独留痕。

## 2.7 退款、终止与调账的最小调整

1. 客户发起退款、接单方同意或拒绝、运营介入、凭证上传等现有线上留痕能力继续保留。
2. 由于客户款项先进入 CSDN，删除“接单方必须直接向客户退款”的唯一限定。
3. 退款由运营根据款项当前实际情况在线下协调执行，可由 CSDN 或经运营确认的责任方完成。
4. 退款完成后，由运营或客户按实际执行情况确认结果并上传凭证；平台不建设原路退款、分润回滚、钱包扣回和追偿能力。
5. 订单终止后的结算继续由运营人工审核并线下执行，不新增自动冻结、自动退款和自动分润。
6. 调账申请和人工调账单继续沿用现有需求，不新增自动计佣、税费和财务计算。

## 2.8 用户侧累计结算展示

1. 原“累计已收款”调整为“累计已结算”。
2. 统计范围为接单方关联且账单状态为已入账的账单。
3. 优先汇总运营确认结算时填写的实际结算金额。
4. 历史账单缺少实际结算金额时，可回退使用账单金额，并在页面注明“历史账单按账单金额统计，具体到账金额以线下结算为准”。
5. 草稿、待确认、待支付、已支付、待退款、已冲销等账单不计入。
6. 本汇总只用于用户总览，不作为财务、税务或会计口径。

## 2.9 开票咨询入口

### 2.9.1 展示条件与位置

1. 客户侧账单达到已支付后，在账单详情展示“开票咨询”区域。
2. 首选位置为客户【我的账单】的账单详情；可在页面顶部增加统一开票咨询入口，但不能替代账单详情中的关联入口。
3. 退款处理中、已冲销、已关闭的账单是否继续展示入口，由运营配置控制；默认已冲销、已关闭不展示。

### 2.9.2 展示内容

- 企业微信客服、企业成员活码或 CSDN 官方客服二维码；
- 联系人或客服名称；
- 开票咨询说明；
- 账单编号、订单编号、账单金额；
- “复制开票信息”操作，复制账单编号、订单编号和账单金额。

### 2.9.3 业务规则

1. 二维码、联系人、说明文案和启用状态由运营后台简单配置。
2. 优先使用企业微信客服、企业成员活码或官方客服二维码，不建议在需求中写死个人微信。
3. 客户扫码后在线下提交发票抬头、税号、邮箱及其他材料；平台不采集、不保存这些开票资料。
4. CSDN 运营、财务在线下判断是否可开票、开票金额、开票内容和处理方式。
5. 平台不记录待开票、开票中、已开票、开票失败、红冲和重开状态。
6. 开票是否完成不影响账单状态和订单已结算判定。
7. 在收款主体与开票主体尚未明确一致前，页面统一使用“开票咨询”，不得表述为“申请开票成功”或承诺一定开具发票。

# 第3章：页面与交互要求

## 3.1 客户侧账单详情

客户侧依账单阶段展示：

1. 待确认：展示金额和业务内容，不展示接单方结算账户。
2. 待支付且未上传凭证：展示 CSDN 收款账户和“我已向 CSDN 完成线下付款”。
3. 待支付且已上传凭证：展示“付款凭证待运营核验”，允许补充凭证或说明。
4. 已支付：展示“CSDN 已确认收款，等待平台结算”和开票咨询入口。
5. 已入账：展示“平台已完成结算”和开票咨询入口。

## 3.2 接单方账单详情

1. 草稿：填写金额、接单方结算账户和说明。
2. 待确认/待支付：可在锁定前修改接单方结算账户；提示客户统一向 CSDN 付款。
3. 付款凭证待核验：展示状态，不提供确认客户收款操作。
4. 已支付：展示“CSDN 已收款，待平台结算”和已锁定的接单方结算账户。
5. 已入账：展示实际结算金额、结算时间、流水号/凭证摘要和账户快照。
6. 如有异议：使用现有申诉入口。

## 3.3 运营侧账单管理

1. 在现有账单列表中支持识别“待支付且客户已上传凭证”的账单。
2. 账单详情提供“确认 CSDN 已收款”和“驳回补证”。
3. 已支付账单详情提供“确认已完成结算”。
4. 运营可查看 CSDN 收款账户快照、接单方结算账户、客户付款凭证和结算凭证。
5. 不新增独立财务工作台、分润工作台或对账中心。

## 3.4 运营简单配置

在现有运营配置中增加两个轻量配置区域：

1. CSDN 收款账户配置：户名、开户行、账号、付款说明、启用状态。
2. 开票咨询配置：二维码、联系人/客服名称、咨询说明、启用状态。

不新增复杂菜单层级、审批流和多账户管理。

# 第4章：验收准则

| 编号 | 场景 | Given | When | Then |
|---|---|---|---|---|
| AC-01 | 接单方填写结算账户 | 正额账单处于草稿 | 接单方填写金额和结算账户并提交 | 账单进入待确认；客户看不到结算账户 |
| AC-02 | 客户查看 CSDN 收款账户 | 账单已确认并进入待支付 | 客户查看账单详情 | 页面展示 CSDN 收款账户，不展示接单方结算账户 |
| AC-03 | 客户上传付款凭证 | 账单待支付 | 客户提交流水号/备注和凭证 | 账单仍为待支付，并显示付款凭证待运营核验 |
| AC-04 | 运营驳回补证 | 客户已上传凭证 | 运营填写原因并驳回 | 客户收到补证通知；账单保持待支付 |
| AC-05 | 运营确认 CSDN 收款 | 财务线下确认已到账 | 运营点击确认 CSDN 已收款 | 账单进入已支付；记录操作者和时间；结算账户锁定 |
| AC-06 | 接单方不确认客户收款 | 账单已上传付款凭证或已支付 | 接单方查看账单 | 不存在确认客户付款到账按钮 |
| AC-07 | 运营确认完成结算 | 账单已支付，线下已向接单方转账 | 运营填写实际结算金额和凭证并确认 | 账单进入已入账，保存结算账户快照 |
| AC-08 | 订单不提前已结算 | 正额应结账单仅为已支付 | 系统校验订单结算条件 | 订单保持待结算 |
| AC-09 | 订单完成结算 | 全部正额应结账单均已入账，其他账单已合法闭环 | 系统校验订单结算条件 | 订单进入已结算 |
| AC-10 | 接单方账户隐私 | 客户查看任意账单详情 | 页面加载账单信息 | 不返回、不展示接单方结算账户字段 |
| AC-11 | 账户锁定 | 运营已确认 CSDN 收款 | 接单方尝试修改结算账户 | 系统禁止直接修改并提示联系运营 |
| AC-12 | 累计已结算 | 用户存在多笔已入账账单 | 用户查看汇总 | 优先按实际结算金额汇总，不计入未入账账单 |
| AC-13 | 开票咨询入口 | 客户账单已支付，配置已启用 | 客户查看账单详情 | 展示二维码、说明和复制开票信息操作 |
| AC-14 | 开票不影响结算 | 客户未联系运营或开票未完成 | 账单和订单推进 | 开票情况不阻塞已支付、已入账和订单已结算 |
| AC-15 | 开票配置停用 | 运营关闭开票咨询配置 | 客户查看账单详情 | 不展示二维码入口，不影响其他账单功能 |
| AC-16 | 无尾款 | 尾款草稿选择无尾款 | 双方完成现有确认 | 不要求两类账户和资金确认，尾款按现有规则完结 |
| AC-17 | 0 元尾款 | 尾款金额为 0 | 双方完成现有完整确认留痕 | 不发生实际付款和转账，不要求运营虚构资金确认 |

# 第6章：埋点与非功能要求

## 6.1 最小埋点

| 事件 | 触发时机 |
|---|---|
| 接单方结算账户提交 | 接单方保存账单草稿成功 |
| 客户付款凭证提交 | 客户提交付款凭证成功 |
| 付款凭证驳回 | 运营驳回补证成功 |
| CSDN 收款确认 | 运营确认 CSDN 已收款成功 |
| 结算完成确认 | 运营确认已完成结算成功 |
| 开票咨询入口点击 | 客户点击二维码区域或复制开票信息 |

不建设财务指标、对账指标和分润指标体系。

## 6.2 非功能要求

- **权限与隐私**：接单方结算账户属于敏感信息，客户接口和页面不得返回；接单方仅查看本人账户，运营按既有权限查看。
- **脱敏**：列表和非操作场景默认脱敏银行卡号；运营执行线下结算时可在详情查看完整信息。
- **审计**：运营确认收款、确认结算、锁定后修改结算账户必须记录操作者、时间、原因和附件。
- **附件**：付款凭证、结算凭证和二维码图片沿用平台通用附件格式、大小与存储规则。
- **历史数据**：存量已支付、已入账账单保持原状态和历史账户信息，不反向补录新的运营确认动作；新规则仅作用于切换后进入待支付的新账单或经运营明确迁移的未支付账单。
- **配置可用性**：未配置启用的 CSDN 收款账户时，正额账单不得进入可付款状态，并提示运营完成配置。

# 第7章：依赖与待确认事项

## 7.1 外部依赖

1. 甲方运营、财务需提供当前有效的 CSDN 收款账户。
2. 甲方财务需在线下向运营反馈客户款项到账结果。
3. 甲方财务、会计需在线下完成抽成及向接单方转账，并向运营反馈结算结果。
4. 甲方需提供可长期使用的企业微信活码或官方客服二维码及开票咨询文案。

## 7.2 上线前必须确认

1. CSDN 收款账户由哪个运营人员维护，变更时如何通知相关人员。
2. 客户付款凭证是否强制上传；若不强制，至少流水号或备注是否必填。
3. 接单方结算账户采用每张账单填写，还是后续从默认账户带入。本期默认每张账单填写。
4. 运营确认完成结算时，“实际结算金额”是否必填。本需求建议必填但不做金额校验。
5. 收款主体与开票主体是否一致或已存在明确开票安排；未确认前统一使用“开票咨询”文案。
6. 开票咨询使用企业微信活码、官方客服二维码还是其他长期有效入口。

# 第8章：最终范围结论

本需求通过双账户和两次运营确认完成最小改造：

- 客户付款使用 CSDN 收款账户；
- CSDN 向接单方转账使用接单方结算账户；
- 客户上传凭证后由运营确认 CSDN 收款；
- 甲方在线下完成抽成、会计处理和转账后，由运营确认完成结算；
- 平台仅记录账户、凭证、实际结算结果和状态，不建设财务系统；
- 客户通过开票咨询二维码联系运营，开票在线下处理且不影响订单结算。

该范围满足线下款统一进入 CSDN、再由 CSDN 向接单方结算的业务要求，同时将系统改造控制在现有账单、运营确认、消息通知和简单配置能力内。
