# CSDN 线下支付归集与结算留痕产品需求说明书

## 需求概览

### 核心摘要

本需求对订单平台现有线下支付路径进行最小范围调整。客户不再向接单方账户直接付款，而是统一向 CSDN 指定收款账户线下付款；接单方继续填写自己的结算账户，供 CSDN 在线下完成抽成、会计处理后向其转账。订单平台不参与真实资金执行，不计算佣金、税费或接单方净收入，仅记录账单金额、两类账户、客户付款凭证、运营确认 CSDN 已收款、运营确认 CSDN 已向接单方完成结算等业务结果。

账单状态继续复用现有枚举：客户上传付款凭证后，账单保持待支付并显示“付款凭证待运营核验”；运营根据线下财务反馈确认 CSDN 已收款后，账单进入已支付；运营根据线下财务反馈确认已完成向接单方结算后，账单进入已入账。正常正额账单只有达到已入账，才计入订单已结算判定。

客户发单时必须选择**业务结算模式**（平台抽佣 / 平台承包转包），用于确定后续里程碑、验收和结算内容的定义及确认主体。平台不提供“整单结算 / 按阶段结算”二选一配置，所有订单均按里程碑生成账单：每个里程碑验收通过后生成对应账单；如发单方希望实现整单结算效果，只需为订单配置一个覆盖全部交付内容和全部款项的里程碑。无论选择哪种业务结算模式，线下资金路径均统一为“客户付款至 CSDN → CSDN 线下处理后向接单方结算”，不再存在客户直接向接单方付款的例外。

客户开票需求通过账单详情中的“开票咨询”入口承接。平台展示运营配置的企业微信或官方客服二维码及账单信息，客户扫码后在线下提交开票资料，由 CSDN 运营、财务在线下处理。平台不建设开票申请单、抬头管理、发票状态、发票文件或红冲能力。

### 文档定位与适用优先级

本文件为《账单与结算产品需求说明书》的专项补充需求，适用于线下支付归集、CSDN 收款确认、向接单方结算留痕及开票咨询入口。

- 本文件与现有需求中“客户向接单方账户直接付款”“接单方确认客户付款到账”等内容冲突时，以本文件为准。
- 本文件补充发单时的**业务结算模式**选择，并明确所有订单统一按里程碑结算；发单方需要整单结算效果时，通过仅配置一个里程碑实现，不新增独立的整单结算选项。相关规则与《客户发布订单与审核产品需求说明书》《里程碑确认与交付验收产品需求说明书》《账单与结算产品需求说明书》冲突时，以本文件对线下归集路径的最新口径为准。
- 未在本文件中调整的金额确认与改价、账单关闭、申诉、退款申请、终止结算和调账规则，继续沿用现有需求；无尾款、0 元尾款仅用于兼容历史尾款账单。
- 本文件只以 `docs/` 下现有需求文档为业务依据，不以原型实现反推需求逻辑。

# 第1章：概述

## 1.1 背景与问题

现有线下支付流程由接单方填写收款账户，客户直接向接单方付款并上传凭证，接单方确认收款后推进账单状态。该路径使订单平台仅记录双方直付结果，客户款项未经过 CSDN 统一归集，平台无法落实“客户向 CSDN 付款、CSDN 完成抽成后再向接单方结算”的业务要求。

甲方要求线下支付同样先进入 CSDN 指定账户。真实到账核验、平台抽成、会计记账、税务处理及向接单方转账均由甲方财务、会计和运营在线下完成，订单平台只需提供必要账户信息、凭证上传、人工确认和状态留痕，不建设完整财务结算系统。

## 1.2 建设目标

1. 客户可在待支付账单中查看 CSDN 指定收款账户，并向该账户完成线下付款。
2. 接单方可填写并维护自己的结算账户，供 CSDN 在线下向其转账。
3. 运营可根据线下财务反馈确认 CSDN 已收款，并记录操作凭证。
4. 运营可根据线下财务反馈确认 CSDN 已向接单方完成结算，并记录实际结算结果。
5. 正额账单只有完成向接单方结算后才计入订单已结算。
6. 客户发单时必须选择平台抽佣或平台承包转包，并明确后续里程碑、验收和结算内容的定义及确认主体。
7. 所有订单统一按里程碑结算；每个里程碑验收通过后生成对应账单，整单结算诉求通过配置单一里程碑实现。
8. 无论采用哪种业务结算模式、配置一个或多个里程碑，客户线下款均统一归集至 CSDN，不允许客户向接单方直接付款。
9. 客户可通过账单详情中的二维码联系运营办理开票，不增加平台开票系统。

## 1.3 非目标

本期明确不建设以下能力：

- 自动计算平台佣金、抽成、税费、手续费或接单方净收入；
- 独立支付单、分润单、结算单、钱包、提现和资金流水系统；
- 银行流水自动读取、自动匹配和自动对账；
- 在线支付、支付回调、自动分润、失败重试和部分成功处理；
- 分润回滚、提现追偿、欠款、垫资和自动原路退款；
- 发票抬头管理、税号校验、开票申请单、开票状态、发票下载和红冲；
- 会计科目、税务处理、财务凭证生成和复杂财务权限体系；
- 部分到账、超额到账、重复付款的自动识别与系统化处理；
- 自动 SLA、超时升级、多级催办和财务运营看板。

上述事项由甲方财务、会计、运营等团队在线下处理。订单平台仅记录账户、凭证、操作结果和必要备注。

## 1.4 用户故事

- 作为客户，我希望在发单时选择平台抽佣或平台承包转包，以便明确后续由我还是平台运营方负责定义和确认里程碑、验收及结算内容。
- 作为客户，我希望通过配置里程碑数量和内容确定结算节奏；如希望整单结算，只配置一个覆盖全部交付内容和款项的里程碑。
- 作为客户，我希望在账单中查看 CSDN 指定收款账户，以便按平台要求完成线下付款。
- 作为客户，我希望上传付款凭证并查看核验结果，以便知道 CSDN 是否已确认收到款项。
- 作为接单方，我希望填写自己的结算账户，以便 CSDN 在线下向我支付结算款项。
- 作为接单方，我希望客户无法查看我的结算账户，以避免不必要的敏感信息暴露和绕过平台直接交易。
- 作为运营，我希望根据财务反馈确认 CSDN 已收款，以便账单状态与线下资金事实保持一致。
- 作为运营，我希望记录 CSDN 已完成向接单方结算，以便账单和订单能够完成闭环。
- 作为客户，我希望在 CSDN 确认收款后扫码联系运营办理开票，以便完成线下开票流程。

## 1.5 术语表

| 术语 | 描述 |
|---|---|
| 业务结算模式 | 客户发单时必须选择的订单级业务模式，包括平台抽佣、平台承包转包；用于确定里程碑、验收和结算内容的定义及确认主体，不改变本需求统一的 CSDN 归集资金路径。 |
| 平台抽佣 | 业务结算模式之一。里程碑、验收和结算内容原则上由客户与接单方共同定义、确认；线下资金仍由客户付至 CSDN，再由 CSDN 向接单方结算。原文“客户与用户直接交易结算”在本需求范围内仅保留业务定义权含义，不再表示客户可直接向接单方付款。 |
| 平台承包转包 | 业务结算模式之一。客户将订单交由平台承接、平台再安排接单方；里程碑、验收和结算内容原则上由平台运营方与接单方定义、确认；客户仍向 CSDN 付款。 |
| 里程碑结算 | 平台统一采用的账单生成规则：每个已生效里程碑验收通过后生成该里程碑对应的账单草稿。 |
| 单一里程碑结算 | 订单仅配置一个覆盖全部交付内容和全部款项的里程碑；该里程碑通过后生成一笔账单，实现业务上的整单结算效果，但不是独立结算模式。 |
| 多里程碑结算 | 订单配置多个里程碑；每个里程碑通过后分别生成账单并独立完成付款和结算留痕。 |
| CSDN 收款账户 | 客户线下付款使用的 CSDN 指定账户，由运营维护并向客户展示。 |
| 接单方结算账户 | CSDN 在线下向接单方转账使用的账户，由接单方填写，仅接单方和运营可见。 |
| 付款凭证待运营核验 | 客户已上传付款凭证，但运营尚未根据线下财务反馈确认 CSDN 收款；该阶段账单主状态仍为待支付。 |
| CSDN 已收款 | 运营根据线下财务反馈确认 CSDN 已收到客户款项；账单状态为已支付。 |
| 平台已完成结算 | 运营根据线下财务反馈确认 CSDN 已完成抽成、会计处理及向接单方转账；账单状态为已入账。 |
| 实际结算金额 | 运营确认完成结算时记录的、CSDN 实际向接单方支付的金额；仅作留痕，系统不计算、不校验。 |
| 开票咨询 | 客户通过二维码联系 CSDN 运营或客服，在线下提交开票资料并办理开票；不代表平台已受理或承诺开票。 |

# 第2章：功能需求

## 2.0 发单时的结算配置

### 2.0.1 配置项边界

发单时只需要选择**业务结算模式**，不新增“整单结算 / 按阶段结算”的账单生成方式选项：

1. **业务结算模式 `settlement_mode`**：二选一，取值为平台抽佣、平台承包转包，用于确定后续业务定义与确认主体。
2. **结算节奏由里程碑配置决定**：平台统一按里程碑生成账单，不设置 `phase_settlement_enabled` 等订单级开关。
3. 发单方希望分阶段结算时，配置多个里程碑；希望整单结算时，只配置一个覆盖全部交付内容和全部款项的里程碑。
4. **资金路径不作为可选项**。无论业务结算模式及里程碑数量如何，均执行“客户向 CSDN 付款 → 运营确认 CSDN 收款 → CSDN 线下向接单方结算 → 运营确认结算完成”。
5. 订单交付模式（如远程、驻场或其他交付方式）属于交付属性，也不得与里程碑数量及结算节奏混淆。

### 2.0.2 业务结算模式选择

#### 平台抽佣

1. 客户发单时选择“平台抽佣”。
2. 里程碑、总工期、交付验收标准及结算内容原则上由客户提出或编辑，并由接单方确认；交付物由接单方提交，客户负责验收确认。
3. 各里程碑账单的业务金额原则上由接单方填写，客户确认；双方改价与留痕沿用现有账单规则。
4. 为满足本需求的线下归集要求，客户不得直接向接单方付款，而是统一向 CSDN 收款账户付款；CSDN 再按线下实际处理结果向接单方结算。
5. 因此，其他文档中“客户与用户直接交易结算”的旧表述，在本需求范围内只表示客户拥有里程碑、验收及结算内容的主要定义权，不再表示资金可由客户直接支付给接单方。

#### 平台承包转包

1. 客户发单时选择“平台承包转包”。
2. 里程碑、总工期、交付验收标准及结算内容原则上由平台运营方提出或编辑，并由接单方确认；客户可查看与其订单相关的约定和交付结果，但不直接编辑平台与接单方之间的执行性结算内容。
3. 各里程碑账单草稿生成后，账单业务金额由运营依据协议和线下约定填写或审核；客户仍需确认其应付金额和付款事项，接单方填写自己的结算账户。
4. 客户向 CSDN 收款账户付款；CSDN 在线下完成会计处理及向接单方结算，运营分别确认 CSDN 已收款和已完成结算。
5. 本期仍复用同一账单对象和两次运营确认，不拆分“客户对平台应付账单”和“平台对接单方应付结算单”，也不自动计算两者之间的佣金、差额或净收入。

### 2.0.3 按里程碑生成账单

1. 所有订单统一按里程碑结算，不在发单环节提供“整单结算”或“按阶段结算”选项。
2. 每个已生效里程碑在按规则验收通过后，系统为该里程碑创建一笔账单草稿；同一里程碑不得重复生成有效账单。
3. 订单配置多个里程碑时，各里程碑账单分别生成、分别确认，并独立执行客户向 CSDN 付款、运营确认 CSDN 收款、运营确认完成向接单方结算的流程。
4. 发单方希望整单结算时，仅配置一个覆盖全部交付内容、全部验收标准和全部款项的里程碑；该里程碑通过后系统生成一笔账单草稿，即实现整单结算效果。
5. 单一里程碑与多里程碑使用相同的账单状态、账户、付款凭证和运营确认流程，不增加整单账单专用类型或状态。
6. 里程碑账单金额应覆盖该里程碑约定的应结款项。平台不再额外自动生成尾款账单；如确有尾款，应在发单或后续里程碑确认时配置独立的“尾款/最终验收”里程碑。
7. 无尾款、0 元尾款的旧规则仅用于兼容历史订单和历史尾款账单；新订单通过里程碑金额与数量完整表达结算安排。
8. 已入账里程碑账单不因后续订单终止自动回退；未达成里程碑对应账单不生成，已生成但无需继续结算的账单按冲销、关闭、退款或调账规则处理。

### 2.0.4 发单交互与校验

1. AI 对话创建、上传文档 AI 创建、手工创建三种入口均必须收集并保存业务结算模式。
2. AI 可根据订单描述给出业务结算模式建议，但不得自行替客户最终确认；进入订单预览或结构化必填项确认阶段时，客户必须看到并确认实际取值。
3. 发单页面在“排期与预算 / 结算配置”区域展示“业务结算模式”：平台抽佣 / 平台承包转包，不展示整单结算、按阶段结算等选项。
4. 页面明确说明：“平台统一按里程碑结算；希望整单结算时，请仅配置一个覆盖全部交付内容和款项的里程碑。”
5. 业务结算模式为结构化必填项。未选择时，“确认并提交审核”保持不可用，并定位至该字段。
6. 选择平台承包转包时，页面提示“后续里程碑、验收与结算内容主要由平台运营方和接单方确认”；选择平台抽佣时，提示“后续里程碑、验收与结算内容主要由客户和接单方确认”。
7. 所有选项下均固定展示“线下付款统一支付至 CSDN 指定账户，请勿直接向接单方付款”。
8. 订单提交确认弹窗展示业务结算模式、订单报价、接单方式、里程碑结算说明及付款路径说明。

### 2.0.5 保存、审核、修改与锁定

1. **新建草稿、已打回**：客户可修改业务结算模式；重新提交时按最新值进入审核。
2. **待审核**：如允许客户编辑，修改业务结算模式后必须重新触发完整审核，并记录修改前后值；不得仅更新字段而沿用原审核结果。
3. **推广中且尚未确定接单方**：原则上不允许客户直接修改业务结算模式。确需调整时，应撤回或由运营退回后重新审核，避免报名方基于旧规则作出判断。
4. **已确定接单方、协议签署中及后续状态**：业务结算模式锁定，客户和接单方均不可直接修改。确需变更时，由运营依据双方协议进行异常处理并记录原因；若已生成账单，还需同步执行账单冲销、关闭、退款或调账，不允许直接覆盖历史配置。
5. 里程碑数量及内容在里程碑确认阶段按现有规则由定义方与接单方共同确认。若从多个里程碑调整为一个里程碑，或反向拆分，必须在相关账单生成前完成并重新确认；已有账单时不得直接改写历史里程碑。
6. 运营审核订单时必须核对业务结算模式是否与订单内容、预计里程碑安排和接单方式一致。审核通过后，订单详情及后续协议应使用同一份配置快照。
7. 账单生成时保存订单业务结算模式和关联里程碑快照，后续异常调整不得覆盖历史账单快照。

### 2.0.6 模式对后续流程的影响矩阵

| 维度/环节 | 平台抽佣 | 平台承包转包 |
|---|---|---|
| 里程碑与总工期定义 | 客户提出/编辑，接单方确认 | 运营提出/编辑，接单方确认 |
| 交付物验收确认 | 客户 | 运营代表平台执行；客户查看结果 |

### 2.0.8 历史订单兼容

1. 新规则上线后创建的订单必须显式选择业务结算模式，不得以隐式默认值替代客户确认。
2. 存量订单存在整单结算、阶段结算或尾款配置时，继续按历史订单既有配置和已生成账单事实推进，不强制迁移为新里程碑模型。
3. 存量订单缺少业务结算模式时，不得直接推断为平台抽佣。订单尚未确定接单方的，由客户补选并重新审核；已进入协议签署中或后续状态的，由运营依据现有协议补录并留痕。
4. 已生成历史账单不因补录业务结算模式或调整里程碑表述而重新生成；账单继续按原有事实和当前专项规则推进。

## 2.1 双账户规则

### 2.1.1 CSDN 收款账户

1. CSDN 收款账户由运营在后台进行简单维护。
2. 最小配置项包括账户名称、开户行、银行账号、展示说明、二维码或附件说明（如有）、启用状态。
3. 本期只要求存在一条当前启用的 CSDN 收款账户，不建设多账户路由、币种、适用范围、版本审批和历史账户管理。
4. CSDN 收款账户适用于平台抽佣、平台承包转包，以及单一里程碑、多里程碑订单，不按模式或里程碑数量配置不同客户付款账户。
5. 账单进入待支付时，客户侧展示当前启用的 CSDN 收款账户。
6. 账单保存本次付款所使用的 CSDN 收款账户快照，后续后台修改账户不影响历史账单展示。
7. 接单方可查看客户统一向 CSDN 付款的说明，但不得将自己的结算账户提供给客户作为付款账户。

### 2.1.2 接单方结算账户

1. 保留接单方填写收款银行、银行卡号、开户名等能力，字段名称统一调整为“接单方结算账户”。
2. 接单方在账单草稿中填写账单金额、接单方结算账户及必要说明。
3. 客户确认账单时只确认账单金额和业务内容，不查看、不确认、不修改接单方结算账户。
4. 接单方结算账户仅接单方本人和运营可见；列表默认脱敏，详情按权限展示。
5. 接单方可在运营确认 CSDN 已收款前修改结算账户。
6. 运营确认 CSDN 已收款后，接单方结算账户锁定。确需变更时，由接单方联系运营说明情况，运营处理并记录修改原因；本期不新增独立账户变更审批流程。
7. 运营确认完成结算时，保存本次实际使用的接单方结算账户快照；后续账户变化不得影响历史账单。
8. 历史无尾款单据不要求填写接单方结算账户。
9. 历史 0 元尾款账单沿用原“完整流程留痕”规则，仍填写接单方结算账户，但不发生客户付款及 CSDN 向接单方实际转账；新订单不自动生成尾款账单。

## 2.2 账单草稿与客户确认

1. 正常结算账单统一由里程碑验收通过触发：一个里程碑对应一笔有效账单草稿；调账单规则继续沿用现有需求。
2. **平台抽佣**：正额账单草稿由接单方填写账单金额、接单方结算账户及业务说明，客户确认金额和业务内容。
3. **平台承包转包**：正额账单草稿由运营依据协议填写或审核账单金额与业务说明，接单方填写接单方结算账户，客户确认其应付金额和付款事项；平台与接单方之间的实际结算金额由运营在完成结算时另行留痕。
4. 客户收到待确认账单后，只核对金额、关联订单、关联里程碑、款项性质和业务说明。
5. 客户不得看到接单方结算账户，避免敏感信息暴露和客户绕过 CSDN 直接付款。
6. 平台抽佣模式的金额改价及双方重新确认规则继续沿用现有需求；平台承包转包模式下的金额异常由运营协调并重新发起客户确认。接单方结算账户修改不触发客户重新确认。
7. 客户确认金额和业务内容后，账单进入待支付，并关联当前 CSDN 收款账户快照、业务结算模式快照和里程碑快照。

## 2.3 客户向 CSDN 线下付款

### 2.3.1 客户操作

1. 账单处于待支付时，客户侧展示 CSDN 收款账户、账单金额、账单编号、订单编号和付款说明。
2. 客户线下付款后点击“我已向 CSDN 完成线下付款”。
3. 客户填写流水号或付款备注，并上传付款凭证；是否强制上传延续现有配置规则。
4. 系统记录客户提交时间、操作者、凭证附件和流水号/备注。
5. 提交后账单主状态仍为待支付，页面显示“付款凭证待运营核验”。
6. 客户在运营完成核验前可补充凭证或说明；是否允许删除已上传附件沿用平台通用附件规则。

### 2.3.2 异常处理

1. 本期不自动识别付款主体、到账金额、部分付款、超额付款、重复付款或错误账户。
2. 运营发现凭证无效、信息不足或财务未查到款项时，执行“驳回补证”并填写原因。
3. 驳回后账单保持待支付，客户可重新提交凭证。
4. 客户对核验结果有异议时，沿用现有申诉与运营人工处理能力。

## 2.4 运营确认 CSDN 已收款

1. 运营在账单管理中查看待支付且已上传付款凭证的账单。
2. 运营根据甲方财务、会计在线下提供的实际到账反馈进行判断，订单平台不连接银行账户、不验证流水真实性。
3. 运营确认前，应能查看账单金额、CSDN 收款账户快照、客户凭证、流水号/备注和关联订单。
4. 运营点击“确认 CSDN 已收款”，可填写核验备注并上传可选附件。
5. 确认后账单从待支付进入已支付，记录确认人和确认时间；接单方结算账户同时锁定。
6. 已支付表示 CSDN 已收到客户款项，不表示接单方已经收到结算款项。
7. 系统通知客户和接单方：CSDN 已确认收款，等待平台线下结算。
8. 接单方不再拥有“确认客户付款到账”或等同操作，也不再适用原有确认收款时限。

## 2.5 运营确认已向接单方完成结算

1. 账单处于已支付时，运营可查看接单方结算账户完整信息，供甲方财务、会计在线下转账。
2. CSDN 在线下完成平台抽成、会计处理及向接单方转账后，运营执行“确认已完成结算”。
3. 确认表单包括：实际结算金额、结算流水号/说明、可选结算凭证、备注。
4. 实际结算金额由运营根据线下结果填写，只作留痕；系统不根据账单金额计算、不校验平台抽成、税费或其他扣减。
5. 运营确认时保存本次实际使用的接单方结算账户快照、操作者和确认时间。
6. 确认后账单从已支付进入已入账。
7. 接单方不需要再次确认到账。如接单方对结算结果有异议，沿用现有申诉入口，由运营人工处理。
8. 未完成线下结算时，账单保持已支付；本期不增加分润中、分润失败、部分成功或自动重试状态。

## 2.6 账单与订单状态协同

### 2.6.1 状态定义

| 账单状态 | 本需求下的业务含义 |
|---|---|
| 草稿 | 接单方待填写金额和接单方结算账户。 |
| 待确认 | 客户待确认金额和业务内容。 |
| 待支付 | 等待客户向 CSDN 付款；客户上传凭证后仍保持该状态，并显示待运营核验。 |
| 已支付 | 运营已确认 CSDN 收到客户款项，尚未确认完成向接单方结算。 |
| 已入账 | 运营已确认 CSDN 完成向接单方结算。 |
| 待退款/退款待客户确认 | 线下退款过程留痕，实际退款由运营协调。 |
| 已冲销/已关闭 | 沿用现有定义。 |

### 2.6.2 订单已结算判定

1. 正常正额账单必须达到已入账，才视为该账单完成结算。
2. 账单仅达到已支付时，订单继续保持待结算。
3. 订单下全部已验收里程碑对应的应结账单均达到已入账，或按现有规则合法关闭、冲销、退款结案后，订单方可进入已结算。
4. 历史无尾款记录经原有双方确认流程完结后，继续视为尾款侧已闭环。
5. 历史 0 元尾款账单不发生实际付款和转账，完成原有账单确认留痕后视为闭环，不要求运营虚构确认收款或结算动作。
6. 已终止订单继续保持已终止，不因历史账单已入账而改为已结算；终止后结算结果按现有规则单独留痕。

## 2.7 退款、终止与调账的最小调整

1. 客户发起退款、接单方同意或拒绝、运营介入、凭证上传等现有线上留痕能力继续保留。
2. 由于客户款项先进入 CSDN，删除“接单方必须直接向客户退款”的唯一限定。
3. 退款由运营根据款项当前实际情况在线下协调执行，可由 CSDN 或经运营确认的责任方完成。
4. 退款完成后，由运营或客户按实际执行情况确认结果并上传凭证；平台不建设原路退款、分润回滚、钱包扣回和追偿能力。
5. 订单终止后的结算继续由运营人工审核并线下执行，不新增自动冻结、自动退款和自动分润。
6. 调账申请和人工调账单继续沿用现有需求，不新增自动计佣、税费和财务计算。

## 2.8 用户侧累计结算展示

1. 原“累计已收款”调整为“累计已结算”。
2. 统计范围为接单方关联且账单状态为已入账的账单。
3. 优先汇总运营确认结算时填写的实际结算金额。
4. 历史账单缺少实际结算金额时，可回退使用账单金额，并在页面注明“历史账单按账单金额统计，具体到账金额以线下结算为准”。
5. 草稿、待确认、待支付、已支付、待退款、已冲销等账单不计入。
6. 本汇总只用于用户总览，不作为财务、税务或会计口径。

## 2.9 开票咨询入口

### 2.9.1 展示条件与位置

1. 客户侧账单达到已支付后，在账单详情展示“开票咨询”区域。
2. 首选位置为客户【我的账单】的账单详情；可在页面顶部增加统一开票咨询入口，但不能替代账单详情中的关联入口。
3. 退款处理中、已冲销、已关闭的账单是否继续展示入口，由运营配置控制；默认已冲销、已关闭不展示。

### 2.9.2 展示内容

- 企业微信客服、企业成员活码或 CSDN 官方客服二维码；
- 联系人或客服名称；
- 开票咨询说明；
- 账单编号、订单编号、账单金额；
- “复制开票信息”操作，复制账单编号、订单编号和账单金额。

### 2.9.3 业务规则

1. 二维码、联系人、说明文案和启用状态由运营后台简单配置。
2. 优先使用企业微信客服、企业成员活码或官方客服二维码，不建议在需求中写死个人微信。
3. 客户扫码后在线下提交发票抬头、税号、邮箱及其他材料；平台不采集、不保存这些开票资料。
4. CSDN 运营、财务在线下判断是否可开票、开票金额、开票内容和处理方式。
5. 平台不记录待开票、开票中、已开票、开票失败、红冲和重开状态。
6. 开票是否完成不影响账单状态和订单已结算判定。
7. 在收款主体与开票主体尚未明确一致前，页面统一使用“开票咨询”，不得表述为“申请开票成功”或承诺一定开具发票。

| 查看开票咨询入口 | 是 | 否 | 可配置 |

# 第3章：页面与交互要求

## 3.0 客户发单与订单详情

### 3.0.1 发单页

1. 在结构化必填项区域新增或补回“业务结算模式”卡片/表单项，不新增账单生成方式选项。
2. 业务结算模式采用单选卡：
   - 平台抽佣：客户与接单方共同确认里程碑、验收及结算内容；客户款仍统一付至 CSDN。
   - 平台承包转包：平台运营方与接单方确认里程碑、验收及结算内容；客户款统一付至 CSDN。
3. 页面展示里程碑结算说明：“平台统一按里程碑生成账单；希望整单结算时，请只配置一个覆盖全部交付内容和款项的里程碑。”
4. 页面固定展示线下付款提示：“无论选择哪种模式，均请向 CSDN 指定账户付款，请勿直接向接单方付款。”
5. AI 已识别或推荐业务结算模式时，使用“AI 建议”标识，不得替代客户主动确认。
6. 提交前确认弹窗展示：业务结算模式、订单报价、接单方式、里程碑结算说明及付款路径说明。

### 3.0.2 订单详情

1. 客户、接单方和运营可在订单详情查看业务结算模式、里程碑列表及结算说明。
2. 接单方在报名、确认接单或查看指定订单时，应能看到业务结算模式，并明确订单统一按里程碑生成账单。
3. 客户详情展示“付款对象：CSDN 指定账户”；不得展示接单方结算账户。
4. 订单进入协议签署中后，业务结算模式以只读方式展示；如运营进行了异常变更，展示变更记录或最新有效版本，并保留历史值。
5. 每个里程碑区域展示“该里程碑验收通过后将生成对应账单”；订单仅有一个里程碑时，可补充展示“当前为单一里程碑，验收通过后生成一笔账单”。

## 3.1 客户侧账单详情

客户侧依账单阶段展示：

1. 待确认：展示金额和业务内容，不展示接单方结算账户。
2. 待支付且未上传凭证：展示 CSDN 收款账户和“我已向 CSDN 完成线下付款”。
3. 待支付且已上传凭证：展示“付款凭证待运营核验”，允许补充凭证或说明。
4. 已支付：展示“CSDN 已确认收款，等待平台结算”和开票咨询入口。
5. 已入账：展示“平台已完成结算”和开票咨询入口。

## 3.2 接单方账单详情

1. 草稿：填写金额、接单方结算账户和说明。
2. 待确认/待支付：可在锁定前修改接单方结算账户；提示客户统一向 CSDN 付款。
3. 付款凭证待核验：展示状态，不提供确认客户收款操作。
4. 已支付：展示“CSDN 已收款，待平台结算”和已锁定的接单方结算账户。
5. 已入账：展示实际结算金额、结算时间、流水号/凭证摘要和账户快照。
6. 如有异议：使用现有申诉入口。

## 3.3 运营侧账单管理

1. 在现有账单列表中支持识别“待支付且客户已上传凭证”的账单。
2. 账单详情提供“确认 CSDN 已收款”和“驳回补证”。
3. 已支付账单详情提供“确认已完成结算”。
4. 运营可查看 CSDN 收款账户快照、接单方结算账户、客户付款凭证和结算凭证。
5. 不新增独立财务工作台、分润工作台或对账中心。

## 3.4 运营简单配置

在现有运营配置中增加两个轻量配置区域：

1. CSDN 收款账户配置：户名、开户行、账号、付款说明、启用状态。
2. 开票咨询配置：二维码、联系人/客服名称、咨询说明、启用状态。

不新增复杂菜单层级、审批流和多账户管理。

# 第6章：埋点与非功能要求

## 6.1 最小埋点

| 事件 | 触发时机 |
|---|---|
| 业务结算模式选择 | 客户在发单流程确认平台抽佣或平台承包转包 |
| 业务结算模式变更 | 客户或运营修改业务结算模式并保存 |
| 里程碑账单创建 | 某一里程碑验收通过并成功创建对应账单草稿 |
| 接单方结算账户提交 | 接单方保存账单草稿成功 |
| 客户付款凭证提交 | 客户提交付款凭证成功 |
| 付款凭证驳回 | 运营驳回补证成功 |
| CSDN 收款确认 | 运营确认 CSDN 已收款成功 |
| 结算完成确认 | 运营确认已完成结算成功 |
| 开票咨询入口点击 | 客户点击二维码区域或复制开票信息 |

不建设财务指标、对账指标和分润指标体系。

## 6.2 非功能要求

- **权限与隐私**：接单方结算账户属于敏感信息，客户接口和页面不得返回；接单方仅查看本人账户，运营按既有权限查看。
- **结算配置一致性**：业务结算模式必须在订单创建、审核、详情、协议关联、里程碑、账单生成和运营处理各模块使用同一有效值；所有新订单均按里程碑触发账单，不得出现独立整单/阶段开关。
- **模式权限校验**：里程碑定义、验收确认和账单业务确认接口必须基于订单业务结算模式校验操作角色，不得只依赖前端按钮隐藏。
- **幂等性**：同一订单同一里程碑只允许存在一笔有效正常结算账单草稿；重复验收事件不得重复创建账单，调账单除外。
- **脱敏**：列表和非操作场景默认脱敏银行卡号；运营执行线下结算时可在详情查看完整信息。
- **审计**：运营确认收款、确认结算、锁定后修改结算账户必须记录操作者、时间、原因和附件。
- **附件**：付款凭证、结算凭证和二维码图片沿用平台通用附件格式、大小与存储规则。
- **历史数据**：存量已支付、已入账账单保持原状态和历史账户信息，不反向补录新的运营确认动作；新规则仅作用于切换后进入待支付的新账单或经运营明确迁移的未支付账单。
- **配置可用性**：未配置启用的 CSDN 收款账户时，正额账单不得进入可付款状态，并提示运营完成配置。

# 第7章：依赖与待确认事项

## 7.1 外部依赖

1. 甲方业务、运营需确认平台抽佣与平台承包转包下的里程碑、验收和账单确认职责分工，并保证协议模板与页面文案一致。
2. 甲方运营、财务需提供当前有效的 CSDN 收款账户。
3. 甲方财务需在线下向运营反馈客户款项到账结果。
4. 甲方财务、会计需在线下完成抽成及向接单方转账，并向运营反馈结算结果。
5. 甲方需提供可长期使用的企业微信活码或官方客服二维码及开票咨询文案。

## 7.2 上线前必须确认

1. 平台承包转包模式下，客户对应付金额的确认是普通账单确认还是只读确认；本需求默认客户仍需确认其应付金额，但由运营主导结算内容。
2. 平台承包转包模式下，交付验收是否全部由运营执行，还是客户保留最终验收意见入口；本需求默认运营执行系统确认、客户可查看结果。
3. CSDN 收款账户由哪个运营人员维护，变更时如何通知相关人员。
4. 客户付款凭证是否强制上传；若不强制，至少流水号或备注是否必填。
5. 接单方结算账户采用每张账单填写，还是后续从默认账户带入。本期默认每张账单填写。
6. 运营确认完成结算时，“实际结算金额”是否必填。本需求建议必填但不做金额校验。
7. 收款主体与开票主体是否一致或已存在明确开票安排；未确认前统一使用“开票咨询”文案。
8. 开票咨询使用企业微信活码、官方客服二维码还是其他长期有效入口。

# 第8章：最终范围结论

本需求通过“发单选择业务结算模式 + 统一按里程碑结算 + 双账户 + 两次运营确认”完成最小改造：

- 客户发单时选择业务结算模式：平台抽佣或平台承包转包，确定里程碑、验收和结算内容的定义及确认主体；
- 平台不提供整单/按阶段二选一，所有新订单均在里程碑验收通过后生成对应账单；
- 需要整单结算时，只配置一个覆盖全部交付内容和款项的里程碑；需要分阶段结算时配置多个里程碑；
- 任意业务结算模式和里程碑数量均统一执行 CSDN 线下归集与结算留痕；
- 客户付款使用 CSDN 收款账户；
- CSDN 向接单方转账使用接单方结算账户；
- 客户上传凭证后由运营确认 CSDN 收款；
- 甲方在线下完成抽成、会计处理和转账后，由运营确认完成结算；
- 平台仅记录账户、凭证、实际结算结果和状态，不建设财务系统；
- 客户通过开票咨询二维码联系运营，开票在线下处理且不影响订单结算。

该范围满足线下款统一进入 CSDN、再由 CSDN 向接单方结算的业务要求，同时将系统改造控制在现有账单、运营确认、消息通知和简单配置能力内。
